# Minecraft 全景图（Panorama）格式与面序约定

这份文档说明 `panorama_0.png` ~ `panorama_5.png` 到底该怎么摆，以及本项目的代码为什么这么写。
**如果你想自己改 `js/cubemap.js` 里的朝向，请先读完本文。**

---

## 1. 资源包里的位置

```
assets/minecraft/textures/gui/title/background/panorama_0.png
assets/minecraft/textures/gui/title/background/panorama_1.png
...
assets/minecraft/textures/gui/title/background/panorama_6.png   ← 不存在，只有 0~5
```

6 张正方形图，围成一个**从内部观看**的立方体天空盒。原版是 1024×1024。

---

## 2. 面朝向表

| 文件 | 方向 | 屏幕上的直观说法 |
| --- | --- | --- |
| `panorama_0` | 北 north (−Z) | 正前方 |
| `panorama_1` | 东 east (+X) | 右手边（**注意：不是 0 逆时针 90°，见下**） |
| `panorama_2` | 南 south (+Z) | 正后方 |
| `panorama_3` | 西 west (−X) | 左手边 |
| `panorama_4` | 上 up (+Y) | 天顶 |
| `panorama_5` | 下 down (−Y) | 天底 |

坐标系按 Minecraft 习惯：`+X = 东`、`+Y = 上`、`+Z = 南`（右手系）。

**环形顺序（关键）**：`0 → 1 → 2 → 3` 是**从上方俯视时的顺时针**：北 → 东 → 南 → 西。
写代码时最容易犯的错就是把它写成逆时针，那样每张图单独看都正常，拼起来在游戏里全是裂缝。

---

## 3. 图内方向（第二容易错的地方）

每张图内部还有一个“上下左右”。本项目采用的参数化是：

```
世界方向 dir(u, v) ∝ F + R·(2u−1) + U·(1−2v)
```

* `u ∈ [0,1]`：图内**从左到右**（像素列）
* `v ∈ [0,1]`：图内**从上到下**（像素行）
* `F` 该面的朝向，`R` 图内 +x 对应的世界方向，`U` 图内 +y（上方）对应的世界方向

六个面的 `(F, R, U)`：

| 面 | F | R | U |
| --- | --- | --- | --- |
| 0 北 | (0, 0, −1) | (1, 0, 0) 东 | (0, 1, 0) 上 |
| 1 东 | (1, 0, 0) | (0, 0, 1) 南 | (0, 1, 0) 上 |
| 2 南 | (0, 0, 1) | (−1, 0, 0) 西 | (0, 1, 0) 上 |
| 3 西 | (−1, 0, 0) | (0, 0, −1) 北 | (0, 1, 0) 上 |
| 4 上 | (0, 1, 0) | (1, 0, 0) 东 | (0, 0, 1) 南 |
| 5 下 | (0, −1, 0) | (1, 0, 0) 东 | (0, 0, −1) 北 |

四条侧面的 `U` 都是世界上方，也就是**侧面图永远是正立的**（地平线水平，天空在上）。
只有天顶 / 天底两张图的“上”是水平的——这正是最容易搞错的两张。

由这张表可以推出两条直观结论（与 Minecraft Wiki 对 Bedrock 的描述一致）：

* **面 4（上）的下边缘贴着面 0（北）的上边缘**；
  即面 4 图内**下边 = 北**，上边 = 南，左边 = 西，右边 = 东。
* **面 5（下）的上边缘贴着面 0（北）的下边缘**；
  即面 5 图内**上边 = 北**，下边 = 南，左边 = 西，右边 = 东。

把它想成“抬头看天”：你面朝北抬头，视野下方是北、上方是脑后（南），所以天顶图的下边是北。
低头同理，视野上方是北。

## 4. 平面上的相邻关系（12 条棱）

用 `dir(u,v)` 在边界外推一步即可自动得到，本项目全部由几何计算得出（不硬编码），
`tools/selftest.cjs` 会断言下表：

| 面 | 右边缘邻面 | 左边缘 | 上边缘 | 下边缘 |
| --- | --- | --- | --- | --- |
| 0 北 | 1 东 | 3 西 | 4 上 | 5 下 |
| 1 东 | 2 南 | 0 北 | 4 上 | 5 下 |
| 2 南 | 3 西 | 1 东 | 4 上 | 5 下 |
| 3 西 | 0 北 | 2 南 | 4 上 | 5 下 |
| 4 上 | 1 东 | 3 西 | 2 南（反向） | 0 北 |
| 5 下 | 1 东 | 3 西 | 0 北 | 2 南（反向） |

“反向”指两张图的边界像素沿相反方向一一对应——这是立方体展开的正常现象，
只要按 `dir()` 计算就不会错，人工手写邻接表则很容易漏掉。

## 5. 与等距柱状全景（equirectangular）的换算

本项目默认的球面坐标：

```
u = 0.5 + λ/360°        λ = 罗盘方位角，0° = 北，+90° = 东
v = 0.5 − φ/180°        φ = 纬度，+90° = 天顶
dir = (cosφ·sinλ, sinφ, −cosφ·cosλ)
```

也就是：**图片的水平中心 = 正北**，图片水平中线 = 地平线。
界面上「水平朝向」滑块（默认 0°）就是给 λ 加一个偏移，用来决定全景图中心对准哪个方向。

## 6. 关于“哪个方向叫北”这一点

需要说明的是：`panorama_0` 究竟对应世界正北还是正南，对**画面是否有裂缝没有影响**——
整体绕竖直轴转 90° 的整数倍，仍然是一张合法无缝的立方体贴图，游戏里只是起始视角不同
（主菜单本来就在缓慢旋转）。真正致命的是：

1. 环形顺序的**旋向**反了（镜像）→ 满屏裂缝；
2. 天顶/天底图的**图内方向**错了 → 上下两处出现裂缝/错位；
3. 有任何一张图被**镜像**过 → 邻接处不连续。

所以判断一份实现对不对，看的是这三条，而不是“0 是北还是南”。
本项目的 12 条棱邻接关系与上表一致，且接缝检测能实时验证。

## 7. 参考与实测

### 7.1 最硬的证据：官方原版贴图反推

原版 Minecraft 自带的 6 张 panorama 图本身就是一个**真实、无缝**的立方体贴图。
于是可以反过来验证约定：把 6 张图按下标塞进槽位，**枚举全部 4⁶ = 4096 种“每面旋转 k×90°”的组合**，
看哪一种能让 12 条棱两侧的像素差最小。

* 如果本项目的约定与官方一致 → 最优解必然是“全部旋转 0°”，且接缝差异降到面内噪声水平。
* 如果不一致 → 最优解会落在某个非零旋转上，或者接缝差异始终很大。

实测（**Minecraft Java 1.20.1 官方 client.jar** 内的原版 `panorama_0..5.png`）：

| | 得分 | 每条棱平均差异 |
| --- | --- | --- |
| **恒等映射（本项目约定）** | **171.15** | **7.13** |
| 第二好解 `(0,0,0,0,0,2)` | 250.08 | 10.42 |
| 最差解 `(2,3,2,3,2,3)` | 1119.85 | 46.66 |
| 面内相邻像素平均差异（噪声基准） | — | 6.51 |

最优解**恰好是“什么都不用改”**，接缝差异 7.13 与面内噪声 6.51 只差 **1.10 倍**——
也就是说这 6 张图在本项目的约定下拼起来，棱上的像素跳变和图片内部的正常像素跳变一样小，
即**完全无缝**。同时它比第二好解优 1.46 倍、比最差解优 6.5 倍，没有任何歧义。

这段验证可以自己复现：

```bash
# 生成输入（原始贴图版权属 Mojang，请勿提交）：见脚本头部注释
python3 tools/verify_vanilla_convention.py
```

### 7.3 自检做了什么

| 检查 | 说明 |
| --- | --- |
| 面内坐标 ↔ 方向互逆 | 2400 个采样点，误差 < 1e-9 |
| 24 条棱的邻面 | 与第 4 节的表逐条比对 |
| 跨棱一步的落点 | 必须落在邻面边缘 1 个像素以内 |
| 平滑全景投影后的接缝 | 24 条棱的差异应与面内噪声同量级 |
| 对照实验 | 故意交换两个面后，接缝差异必须显著变大（证明检测有效而非恒为真） |
| 投影保真度 | 球面 → 立方体 → 反查方向，颜色最大偏差 < 6/255（实测 0.6） |
| ZIP | CRC-32 标准校验向量 + Python `zipfile` 实际解压验证 |
| 原版贴图反推 | 见 7.1，4096 种旋转组合枚举，最优解 = 恒等映射 |

## 8. 如果你的素材用的是另一套约定

界面上「高级 · 朝向修正」提供了三个补救开关：**上下互换**、**环向反转**、**整体水平旋转 90°**。
其中“整体水平旋转”是真正的三维旋转（内容绕竖直轴转），结果依然无缝；
另外两个是**槽位重排**，用于修正“你以为的 0 号面其实是别人的 2 号面”这类约定差异。

改完点「检查接缝」，数值全部低于阈值就说明拼对了。
